# Aura Protocols — Project Context

## What This Is
A Next.js 16 **retail storefront** for research peptides (Aura Protocols LLC sells its own lot-tested compounds). Formerly an affiliate index — all vendor affiliate links were removed in the 2026-09-27 retail redesign. Old `/go/*` links 301 to our own product pages.

Live at **https://auraprotocols.com** (Vercel project `aura-protocols`; PAUSED until checkout ships). `shop.auraprotocols.com` 301s to the apex.

## Stack
- Next.js 16 (App Router), React 19, TypeScript, Tailwind v4
- Supabase **Aura Store** — Auth (customer accounts, `@supabase/ssr`; email/password + Google) + tables: `gate_attestations`, `subscribers`, `inquiries` (`apps/shop/supabase/storefront.sql`); `customers`, `account_agreements`, `orders`, `order_items`, `stripe_events` (`accounts-checkout.sql`); `account-gate.sql` (customers verify/opt-in columns, `orders.new_account_discount`, `gate_lookups`, `account_id_by_email()`); partner tables in `partners.sql` (partners, aliases, clicks, commissions, adjustments, payout runs/payouts, store-credit ledger; private `w9` bucket); discount codes in `discount-codes.sql` (`discount_codes`, `discount_batches`, `code_redemptions`, `discount_code_events`, `code_attempts`, `shop_settings`; `claim_discount_code` + settle trigger on order status); customer admin in `customers-admin.sql` (`customers.blocked_at/blocked_reason`, `customer_events`, `store_credit_ledger.note`; server-only `admin_customer_list`, `admin_customer_stats`, `admin_adjust_credit`); catalog & lots in `catalog-ops.sql` (`catalog_products`, `catalog_variants` (strengths: label, price, low at, 3PL SKU, shown, archived), `lots`, `lot_holds`, `shipped_lots`, `catalog_events`, `lot_stock` view; server-only `hold_vials`, `admin_lot_live`, `admin_correct_count`, `admin_retire_lot`, `admin_delete_variant`, `record_shipped_lots`, `order_hold_shortfall`, `lot_integrity`, `variant_history` + `settle_holds_on_order_status` trigger; public `coa` bucket, PDF only). Today in `today.sql` (`owner_alerts` — one open row per title; `shop_settings.inquiries_seen_at`; server-only `record_owner_alert`, `admin_sales_summary`). Disputes in `disputes.sql` (`disputes` — one row per Stripe dispute, refreshed by `record_dispute`, which ignores out-of-order events; `early_fraud_warnings`; `dispute_events` activity log with unique `event_key` for webhook/cron entries; server-only `record_dispute`, `admin_disputed_customers`). RLS on, no policies: service role, server only. Supabase **Confirm email is OFF** — our own verification (`lib/account/verify.ts`, `/auth/verify`).
- Stripe hosted Checkout via `lib/commerce.ts` (card, wallets, ACH; Stripe Tax); webhook `app/api/stripe/webhook` → `lib/stripe-events.ts` (`charge.dispute.created/updated/closed/funds_withdrawn/funds_reinstated`, `radar.early_fraud_warning.created/updated` must be enabled on the endpoint); daily reconcile cron `api/cron/reconcile` (missed paid webhooks, expired sessions, orphaned pending orders). Payment methods are set in the Stripe dashboard, not code (runbook in the private repo).
- Amazon SES for email; bounces/complaints arrive via SNS → `api/ses/events`; vitest + Testing Library. Email admin in `email-admin.sql` (`campaigns`, `campaign_recipients`, `email_events`, `email_runs`, `email_admin_events`, `email_sends.skipped`, `shop_settings.welcome_paused/cart_paused`; server-only `email_audience`, `admin_start_campaign`, `admin_email_overview`, `admin_email_send_stats`, `admin_email_attribution`, `admin_cart_recovery`, `admin_email_audience_counts`).
- Partner program: `lib/partners/*` (pure rules: codes, tiers, discounts, payout-math; data: `data.ts`, `ledger.ts`), tables in `apps/shop/supabase/partners.sql`, `/affiliates` (program + calculator), `/partners` (dashboard), `/admin/partners`, `/admin/payouts`, daily cron `api/cron/partners-daily` (clears commission; payouts on the 1st/15th).

## Design System — "Pharmacopoeia" + storefront
- Scope class `.pharmacopoeia` (see `globals.css`). Tokens: paper `#EDE9E0`, paper-deep `#E2DCCC`, ink `#1C1A15`, ink-soft `#4A4438`, specimen `#A32B1F`, line `#C9C2AE`.
- Type: Newsreader display (`--font-newsreader`, italic accent word in specimen), Georgia body, JetBrains Mono micro-labels (`--font-jetbrains`, class `.s-micro`).
- **Square corners, 1px hairlines.** Storefront classes are prefixed `s-` and were ported from the approved mocks in the private repo (`docs/superpowers/specs/2026-09-27-storefront-mocks/`). Port from mocks — never freestyle UI.
- Brand: `AuraLockup` (animated pulse-line A). Vial label art: `components/store/Vial.tsx`.

## Compliance rules (enforced)
- Research use only. No dosing, protocols, reconstitution, benefits, "studied for", or human-outcome language anywhere. Scientific names only; chemical-class categories; no "stack".
- `pnpm --filter @aura/shop build` runs `scripts/compliance-scan.mjs` and FAILS on banned phrases. Fix copy, don't widen the allowlist.
- Account gate: browsing needs an account; the sign-up agreement (21+, RUO, dispute policy) is recorded in `account_agreements` (`gate_attestations` kept for history). The gate fails closed (a failed status check shows it).
- Before unpausing Vercel: `RELEASE_CHECK=1 pnpm --filter @aura/shop test` must pass (every strength on the store has a live certified lot; no placeholder material/testing).

## Conventions
- **Relative imports only** in anything reachable from `next.config.ts` (`data/catalog*.ts`, `lib/catalog.ts`, `lib/redirects.ts`, `lib/constants.ts`). Always verify with a real `next build`.
- `BASE_URL` = `https://auraprotocols.com` in `layout.tsx`, `sitemap.ts`, `robots.ts` — keep in sync.
- New static pages must be added to `sitemap.ts`. Legal pages are linked from `SiteFooter` only.
- Checkout goes through `lib/commerce.ts` (`CommerceAdapter`). Starting a checkout closes the customer's earlier unfinished ones (expires the Stripe page, cancels the order; the cancel trigger returns held store credit).
- Authorization lives in `lib/dal.ts` (`requireCustomer`, `requireOwner`, `requirePartner`, `requireApprovedPartner`) — call it next to every data access. `proxy.ts` refreshes sessions and, for `?ref=`, sets the signed `aura_ref` cookie and counts the click; it does no authorization.
- Order status changes go through `transitionOrder` (`lib/orders.ts`) and the machine in `lib/order-status.ts` — never update `status` directly.
- Prices are rebuilt server-side by `lib/pricing.ts`; never trust cart prices from the browser.
- Discounts go through `lib/discounts/engine.ts` only: per item the larger of pack, partner/new-account percent or an item-% code → an order code (replaces the item discounts if cheaper, or applies on top) → the store-wide cap (`shop_settings.max_discount_pct`, 35, editable CAP_MIN_PCT–CAP_MAX_PCT in `lib/discounts/rules.ts` = new-account % to 60, so the welcome offer is never trimmed; the DB check is a looser 15–60) → free shipping. `orders.partner_discount_cents` = every discount beyond pack price (commission base stays goods paid); `orders.code_discount_cents` = the code's share. One code box per order; admin codes share one namespace with partner codes. Code uses are claimed with the pending order (`claim_discount_code`) and settled by the order-status trigger — never update `code_redemptions.state` directly except the owner's reset. Store credit is a payment, not a discount — tax is pre-computed with Stripe Tax before credit applies.
- Commission changes only through `lib/partners/ledger.ts` (created on payment, clearing on ship, reversed on refund/chargeback). Partner bank/Zelle details are AES-GCM encrypted (`PAYOUT_DETAILS_KEY`).
- Failures must be loud: a write that can fail throws (or alerts the owner via `alertOwner`), never reports success; webhook handlers throw to get a Stripe retry when an order isn't matched yet.
- New-account offer: 25% (NEW_ACCOUNT_PCT; was 15 until 2026-10-06) off a first order within 3 days of sign-up (NEW_ACCOUNT_DAYS), automatic (`lib/account/offer.ts`); every shown percent comes from OFFER_PCT_TEXT/NEW_ACCOUNT_PCT; larger-of with pack (beats every pack tier); beats a partner code but the partner keeps commission.
- Offer panel (`components/account/OfferPanel.tsx`, server component, Ink colours, mock "Ink with garland"): on /finish-account beside the form (stretches to its height) and on /sign-in (layout B: Google + sign-in + create-account in one left column, panel right, sticky, height min(column, 760px)); above the forms on phones. Holiday dressing (tree, snow, garland) only when `isHolidaySeason(currentMs())` — `lib/holiday/season.ts` HOLIDAY_START..HOLIDAY_END (Dec 1 00:00 – Jan 1 23:59 shop time, every year). Tree/garland SVGs are generated deterministically (`lib/holiday/tree.ts`, `garland.ts`, seeded); the garland is size-independent (pattern-filled edge strips + fixed holly corners) and reaches outside the panel, so never put overflow hidden/clip on `.s-offer` or its ancestors (only `.s-offer-snow` clips).
- Google sign-in: one shared `GoogleButton` (`components/account/GoogleButton.tsx`, Google branding) → `startGoogleAction` (`app/auth/google-actions.ts`, Supabase OAuth/PKCE, `prompt=select_account`) → `/auth/callback?flow=google`. A signed-in user with no `customers` row is **unfinished** (`getAccountState().unfinished`): `/api/me/gate` (`finish`), `/sign-in` and `requireCustomer` send them to `/finish-account`, which records the same agreement via `finishGoogleAccount` (`lib/account/create.ts` — shares the one customers + agreements insert with `createAccount`; Google-verified → `email_verified_at` set, no verify email, opt-in completed via `lib/account/welcome.ts`). A customers read error throws (never read as "unfinished"). Same verified email auto-links to the existing account; banned → `/sign-in?error=closed`. Pre-hijack guard: a Google sign-in on a user that also has a password identity and no confirmed email (`email_verified_at` null, or no customers row) replaces the password with a random one and marks the email confirmed (`lib/account/google-link.ts`); if that fails the callback signs out (alert "Google sign-in: old password not removed"). Only a Google identity can finish on `/finish-account` — any other unfinished user is told to sign out and sign up by email. `safeNext` refuses control characters and backslashes and must resolve to our own origin.
- Blocking (admin Customers) = Supabase ban + `customers.blocked_at`; `getAccountState`/`getCustomer` (`lib/dal.ts`) treat a blocked account as signed out (gate shows "closed"); open checkouts close via `closeOpenCheckouts` (`lib/checkout-close.ts`, shared with checkout). Owner store-credit changes go through `admin_adjust_credit` only (same advisory lock as `spend_store_credit`, never below zero) and are logged in `customer_events`.
- Catalog: product content is code in `data/catalog.ts` (new products need code — the copy is compliance-scanned); strengths, prices, show/hide, lots and stock are Aura Store (`catalog-ops.sql`), read through `getLiveCatalog`/`getLiveCatalogOrNull` (`lib/catalog-live.ts`, one cache tag). Storefront pages fail closed (`Unavailable`), never code prices; a Vercel build that can't read the catalog fails. Owner saves call `catalogChangedByOwner()`; cancels/refunds/holds call `catalogStockChanged()`. The store sells a strength only when its product AND the strength are shown and it isn't archived; COA lookup keeps every lot of a shown product.
- Strengths are added in the admin (start hidden), hidden, archived/restored, or deleted only with no lots and no orders (`admin_delete_variant`). `variant_id` is derived from the label ("30 mg" → `30mg`).
- Stock moves only through `hold_vials` (checkout, after the pending order and before the code claim; oldest live lot first, all or nothing), the `settle_holds_on_order_status` trigger (paid → sold, cancelled → released, refund from paid → returned), `admin_correct_count` (reasons incl. "Owner withdrawal": remove only, note required — the owner's-draw record) and `record_shipped_lots` (callers alert on `alert`, refresh on `moved`) — never update `lot_holds` or `lots.adjust_qty` directly. Held/sold/available are derived (`lot_stock`). A lot goes live only with a certificate and a completed receiving check; a live lot's details are fixed.
- 3PL readiness: every count change carries a `source`; order lines keep allocated (`lot_holds`) vs shipped (`shipped_lots`) lots; `catalog_variants.threepl_sku`. Procedures doc for the 3PL: private repo `docs/operations/3pl-stock-and-lot-procedures.md`. The 3PL integration itself is a later plan.
- **Every command-center module ships with its Guide chapter** (`/admin/guide`, `components/admin/guide/`): add it to `chapters.ts` (that also gives its pages the top-bar "How this works" link), write lede → Common tasks → How it works → Watch out for with on-screen labels in `<Ui>`, and take figures from constants, never typed numbers.
- Owner alerts: `alertOwner` (`lib/notify.ts`) logs, stores (`record_owner_alert` — one open alert per title; a repeat counts up and keeps earlier details underneath) and emails; it never throws. **Titles are the dedupe key**: keep them stable — order numbers, ids, run dates, counts and names go at the start of the detail. Done/notes live in `/admin` and `/admin/alerts`.
- Today (`/admin`) reads every section through the modules' own data functions in `lib/today/today.ts` (`Promise.allSettled`, one async function per section, React `cache` shared with the nav count); a section that can't load shows "Couldn't load", never zeros. Sales = goods after discounts of paid/shipped orders by `paid_at`, in shop time (America/Denver), from `admin_sales_summary`. New sections or modules add a slot there, not a second query path.
- Disputes: the webhook records every dispute and early fraud warning (`lib/stripe-events.ts` → `lib/disputes/data.ts`), idempotently, and throws until the order is matched. Evidence = `buildEvidence(facts)` (records) + the owner's 8 edited fields; our copy passes the compliance scan (`lib/disputes/checks.ts`, customer data blanked first) before every Save draft / Submit. The PDF is built from records only (fixed dates → identical bytes for download and Stripe). Stripe calls live in `lib/disputes/stripe.ts`; a Stripe error is shown to the owner and nothing is recorded. Cancel and refund (early warnings, before shipping only) refunds the payment intent, then `transitionOrder` + `afterOrderRefunded`. Deadline reminders: the reconcile cron, `DISPUTE_REMIND_DAYS`, once each (`disputes.reminded`).
- Blocking is never automatic; the dispute page reuses `BlockDialog`/`blockAction`.
- Server Components get the time from `currentMs()` (`lib/clock.ts`), never `Date.now()`.
- Marketing email: campaigns go through `lib/email/campaigns/send.ts` (`sendCampaignBatch`) only — Send now and the hourly cron share it; status changes through `moveCampaign` / `admin_start_campaign` (`lib/email/campaigns/rules.ts` machine). Every send uses `sendTracked`. Pause switches live in `shop_settings`; a paused cart reminder is recorded as a skipped `email_sends` row. Unsubscribe links carry a signed `c=` source tag. Bounces/complaints/unsubscribes are counted in `email_events`.
